# 抖音极速版「看视频 / 看广告 / 逛街 领金币」自动化

一套基于 **ADB + 截图像素识别** 的安卓自动化脚本，用于抖音极速版（`com.ss.android.ugc.aweme.lite`）的赚钱任务。
无 OCR、无 uiautomator 依赖（该 App 的任务页有秒级倒计时，`uiautomator dump` 永远等不到 idle）。

---

## 0. 给 AI agent（Claude Code / Codex / Cursor 等）的接手说明

> 完整版见 [`AGENTS.md`](AGENTS.md)，这里只列最关键的几条。

```bash
python update.py     # 每次会话第一件事：检查并拉取最新版本，会打印 VERSION + commit
python check.py      # 环境自检：adb / 设备 / 分辨率
python dy_coin.py    # 开跑
```

- **不要用 `uiautomator dump`**：任务页有秒级倒计时，dump 永远等不到 idle。
- 所有坐标是 **1080×2400 绝对值**，换分辨率必须重新标定。
- 页面状态判断 = `shot()` 截图 + numpy 像素判据，改判据前先用真机截图取样验证。
- 不在预期页面时**不要连按 BACK**（会退到桌面），判 `PKG not in focus()` 后 `relaunch()`。
- 改完代码请升 `VERSION` 并提交，否则别人的会话拉不到你的修复。

## 3. 业务模型（关键！这是本项目的核心知识）

### 3.1 三个入口都在「赚钱任务」页

从 feed 底部中间的红色 `赚钱` 按钮 `(540, 2310)` 进入。

| 入口 | 坐标 | 说明 |
|---|---|---|
| `去看视频` | `(800, 660)` | 进 feed，观看时长累计到里程档位 |
| `看广告赚金币` 标题文字 | `(300, 2112)` | **注意：点的是标题行 y≈2112，不是描述行** |
| `开宝箱得金币` | `(913, 2216)` | 冷却 12~14 分钟，直接给 5~8 金币，**不播广告** |

> `看广告赚金币` 这一行有 **20 分钟冷却**。冷却中点击**无任何反应**（不弹窗、不跳转），脚本必须能容错跳过。

### 3.2 看视频 = 里程档位

- 里程格是横向一行，`y≈895`，5~6 格
- 每格三态：

| 状态 | 外观 | 是否该点 |
|---|---|---|
| `待领取` | **白底 + 红字金额** | ✅ 点它领奖 |
| `已领取` | 整格淡粉 `(254,145,165)` | ❌ |
| `赚钱中` / `N分钟` | **红底 + 白字金额** | ❌ |

- 判据：金额数字上方 `y795-845` 的底色带，白/浅粉 vs 亮红
- 档位金额会递减：`380 → 3380×3 → 3380 → 2454×N`，时间要求也会变
- **纯静置几乎不计时，必须滑动换视频**才累计
- 领取弹窗：`恭喜获得看视频奖励 +N金币` → 点 `开心收下`

### 3.3 看广告 = 激励视频（ExcitingVideoActivity）

```
点「看广告赚金币」标题
  → ExcitingVideoActivity
     右上角药丸：`💰 43秒后可领奖励 ×`   ← 倒计时
     倒计时结束 → `领取成功 ×`
  → 弹窗（**两种状态，必须区分**）
```

**两种弹窗状态**（这是最容易写错的地方）：

| | 等待态 | 完成态 |
|---|---|---|
| 标题 | `再看27秒可领奖励` | `再看一个视频额外获得 +118金币` |
| 主按钮（亮粉药丸） | **`继续观看`** | **`领取奖励`** |
| 药丸下方 | `坚持退出` + `换一个`（**两段**） | `坚持退出`（**一段**） |
| 正确动作 | 点 `继续观看`，等倒计时走完 | 点 `坚持退出` |

判据：`ad_waiting()` 数药丸下方文字行的段数，`>=2` 段就是等待态。
把等待态误判成完成态会导致**只差几十秒的奖励被放弃**，而且是老 bug，改判据务必回归测试。

```
  → 点「坚持退出」
  → 可能跳落地页 SifContainerActivity（如「红果免费短剧」）→ BACK
  → 回任务页弹「恭喜累计获得奖励 N金币」→ 点「评价并收下金币」
```

- 右上角药丸几何：`x577-1025, y77-202`，`×` 中心 `(982, 130)`
- `×` 点击**无效**（实测点击后截图字节完全一致），必须点 `坚持退出` `(539, 1457)`
- `领取奖励`（再看一个）在 `(539, 1315)`

### 3.4 逛街得金币（BulletContainerActivity）

**入口**：任务页 `看广告赚金币` 正下方 → `逛逛顶赚钱 ￥669`
`浏览低价商品90秒即得669金币，每日可完成 0/15 次`

```
点「逛逛顶赚钱」
  → 顶部「逛街得金币」+「浏览90秒可领669金币」
  → 首次弹窗「再看N秒可获得奖励 +669金币」→ 点「继续观看」(只点一次!)
  → 右下角红包倒计时浮标 (x870-998, y1800-1963)
       必须上下滑动页面才计时
  → 倒计时结束浮标收起，奖励自动到账
```

**关键坑**
- 页面滚动后顶部标题移出屏幕 → 页面类型**只能**用 `mCurrentFocus` 含 `bulletcontainer` 判断
- 「再看N秒」弹窗**只点一次**。反复点会不断重新弹，比正常滑动更耗时
- 滑动别太频繁：2~3 秒一次会打断计时，实测 158 秒才完成 90 秒任务。改成 4.5~7 秒一次
- **每日 15 次**，是性价比最高的任务（90 秒 669 金币），应排在广告之前

## 4. 策略

**视频优先 → 逛街/广告交错**

每轮：
1. 回任务页 → 只点 `待领取` 格领奖
2. 档位 ≥1000 → 点 `去看视频` → `dy_auto(fast=True)` 刷视频 → 回来领奖（最多 6 轮）
3. 逛街区：点 `逛逛顶赚钱`
   - 进得了 H5 页 → 滑动浏览 90 秒，完成一次，继续下一次
   - **进不去（冷却中）→ 立刻转去看广告**，广告做完再回来试逛街
4. 剩余广告补做
5. 顺带：开宝箱、签到

逛街冷却的标志：点击后不跳 `BulletContainerActivity`；任务页描述会变成
`07:26后浏览还可得金币，每日可完成2/15次`。

### 刷视频用 `fast` 模式

`dy_auto.py` 原本是为**模拟真人看视频**设计的，单条停留最长 180 秒、还有 25~150 秒的休息。
但里程**只认切换视频后的有效浏览**，长停留等于浪费。`fast=True` 时：

| 参数 | 原值 | fast |
|---|---|---|
| 单条停留 | 平均 22.2s / 最长 180s | 平均 9.4s / 最长 16s |
| 滑后等待 | 2.0~11.0s | 1.2~4.5s |
| 休息间隔 | 每 22~42 次 | 每 40~80 次 |
| 休息时长 | 25~150s | 6~22s |

效果：8 分钟从 12 次上滑提升到 **35 次**。

## 5. 状态识别（全部实测标定）

| 状态 | 判据 |
|---|---|
| feed | `(540,2310)` 亮红（赚钱按钮） |
| 任务页 | `(540,350)` 粉红 `(255,79,116)` **且** `(540,2310)` 白 |
| 有弹窗/遮罩 | `(540,2310)` 变暗（<135） |
| 广告页 | `mCurrentFocus` 含 `excitingvideo` |
| 逛街页 | `mCurrentFocus` 含 `bulletcontainer` |
| UP 主主页 | `y300-420` 平均亮度 >200 **且** `(600,540)` 很暗 |
| 直播间 | `y1940-2115, x10-240` 品红 `#F52A81` 像素 >800 |

**弹窗主按钮要按颜色找，不能写死 y**（三种弹窗位置不同）：

| 弹窗 | 按钮 | 位置 |
|---|---|---|
| 领取（开心收下/红） | 红 | `y1408-1557` → `(540,1482)` |

## 6. 踩过的坑（重要）

| 坑 | 现象 | 解决 |
|---|---|---|
| `uiautomator dump` 卡死 | 任务页有秒级倒计时，永远 "could not get idle state" | 放弃 UI dump，全用像素 |
| `adb_text` 被误删 | `NameError: adb_text is not defined`，空转刷日志 | 补回函数 |
| hook 把任何非 feed 页当弹窗 | 误入 UP 主主页后死循环点 `(540,1531)` | hook 只在 `is_dialog_open()` 时点弹窗；主页单独 BACK |
| 盲点所有里程格 | 点到 `赚钱中` 无反应，点到别的可能跳页 | 只点 `待领取`（**鲜红字 + 白底**） |
| `已领取` 被误判成 `待领取` | 待领取格子越积越多却领不掉 | 已领取金额是**淡粉** `(255,199,210)`，待领取是**鲜红** `(254,48,87)` |
| 任务行写死 y | 页面滚动后点空 | `find_task_row()` 用左侧图标颜色动态定位（AD 徽标 vs 紫色店铺图标） |
| `看广告` 点错行 | 点 y2024 无反应 | 标题在 y≈2112（滚动后不同，用动态定位） |
| 广告页点 `×` | 无反应（截图字节相同） | 点 `坚持退出` |
| 逛街静止不计时 | 52s→50s | 必须上下滑动 |
| 逛街弹窗反复弹 | 每 8 秒点一次，越点越弹 | 弹窗**只处理一次**，之后不再检测 |
| 逛街滑动太频繁 | 158 秒才完成 90 秒任务 | 滑动间隔放宽到 4.5~7 秒 |
| `find_dialog_button` 在 H5 页误判 | 点到「立即购买」跳进下单页 | 加 `is_dialog_open()`：四角变暗 + 中间白卡才算弹窗 |
| 无线端口漂移 | 掉线 | `ensure_device()` 用 mdns 重发现，失败回退 USB |
| 双开抢设备 | 两个进程交替点击，日志交错、行为混乱 | `coin.lock` 单实例锁（PID 校验，进程死了自动接管） |
| 等待态被当完成态 | 广告页反复点「坚持退出」200+ 次，卡 20 分钟 | `ad_waiting()` 数药丸下方文字段数 |
| 残留锁文件 | 重启后提示「已有实例在运行」但没进程 | 锁里存 PID，用 `tasklist` 校验存活，失效自动覆盖 |
| 多设备/分辨率不符 | 点空、坐标全错 | `dy_env.pick_serial()` + `check_screen()` 前置拦截 |
| 误点进提现页 | 危险 | `escape_to_task` 遇未知页 BACK + 必要时重启 App |

## 7. 代码结构（`dy_coin.py`）

```
adb/online/ensure_device/adb_text/focus/tap/swipe/back/shot   ← 基础
is_feed / is_task / is_dim / is_profile / is_live             ← 页面判定
is_ad / ad_exit_dialog / handle_ad_page                       ← 激励视频
is_shop / shop_countdown / handle_shop                        ← 逛街
find_pending / claim_milestones                               ← 领奖
find_dialog_button / handle_dialog                            ← 弹窗
escape_to_task / go_feed / relaunch                           ← 恢复
do_ad / do_chest / do_signin / watch_feed                     ← 任务动作
read_tier / one_round / main                                  ← 主循环
```

`dy_auto.py` 对外只暴露 `main(minutes, on_tick)`：
- `on_tick()` 每轮调用，返回 `True` 表示外部已处理（广告页/弹窗/主页），跳过本轮观看
- 内部：折线 `motionevent` 滑动、对数正态重尾停留、红包环驱动、犹豫半滑/回看/点赞、直播间 3 秒跳过

## 8. 迁移到新环境

**先跑 `python check.py`**，它会逐项检查依赖 / adb / 设备 / 分辨率 / 抖音安装 / 当前窗口。

正常情况下**不用改代码**，只设环境变量：

```bash
export ADB_BIN=/path/to/adb          # 找不到 adb 时
export ADB_SERIAL=xxxxx              # 多设备时
export DY_DEV_HOST=192.168.1.20      # 无线调试
```

只有这几种情况需要改代码：

1. **屏幕分辨率不是 1080×2400** → 重新标定：
   - 所有 `XY_*` 坐标
   - `MILE_BOXES` 五个格子 x 区间、`MILE_Y`、`MILE_BG_Y` 底色带
   - `find_task_row()` 里的图标颜色阈值
   - 三种弹窗按钮的 y 区间
2. **App 版本更新导致布局变化** → 同上，重新截图标定（把新截图和旧判据对比）
3. **换 App / 换包名** → 改 `PKG`
